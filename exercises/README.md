# Практика (учебные задания)

Модуль с учебными заданиями для раздела **«Практика»** в приложении.

Идея (вариант A): код заданий и тесты лежат прямо в репозитории, вы пишете
решение локально в обычном редакторе, а приложение лишь **показывает**
результаты прогонов. Сервер ничего не исполняет: никакой песочницы, Docker и
запуска чужого кода.

## Структура

Вложенность папок — это вложенность тем на фронтенде (любой глубины).
Папка, в которой есть `*_test.go`, считается **заданием** и имеет свой пакет
(изоляция: ошибка компиляции в одном задании не ломает остальные).

```
exercises/
  go.mod
  internal/exercise/         # помощник: пишет результат прогона
  golang/
    topic.json               # {"title": "Golang"}
    osnovy/
      topic.json             # {"title": "Основы"}
      sum/                   # задание = папка (пакет)
        task.json            # {"title": "...", "description": "..."}
        sum.go               # сюда пишем решение
        sum_test.go          # тесты + TestMain (не трогаем)
      factorial/
    stroki/
      reverse/
      palindrome/
```

- `topic.json` — заголовок темы (иначе имя папки; числовой префикс `01-`
  отбрасывается). `task.json` — заголовок и описание задания (необязателен).

## Как решать

1. Реализуйте функцию в `<тема>/<задание>/<файл>.go` так, чтобы прошли тесты
   из соседнего `*_test.go`.
2. Прогоните тесты **любым привычным способом** — статус обновится сам:

   ```sh
   cd exercises
   go test ./...                     # все задания
   go test ./golang/osnovy/sum/      # одно задание
   go test ./golang/stroki/...       # тема с подтемами
   go test -run TestSum ./golang/osnovy/sum/
   ```

   То же самое работает кнопкой «run test» в редакторе.

3. Откройте раздел **«Практика»** — решённые задания будут зелёными. Для
   упавших раскройте «Вывод теста».

## Как это работает

В каждом тестовом файле есть:

```go
func TestMain(m *testing.M) { exercise.Main(m) }
```

`exercise.Main` перехватывает вывод тест-бинарника, прогоняет тесты и
записывает результат в `exercises/.results/<путь пакета>.json`. Поэтому не
нужно никаких отдельных команд и отчётов: обычный `go test` уже фиксирует
статус. Сервер читает `.results/` и показывает дерево.

## Важно

- `.results/` не хранится в git (артефакт прогонов).
- Успешные пакеты `go test` кэширует и может не запускать бинарник повторно —
  это нормально: файл результата уже лежит на месте. Провалившиеся тесты кэш не
  использует, они перезапускаются. Если удалить `.results/` при «горячем» кэше,
  добавьте `-count=1`.
- Ошибки **компиляции** тест-бинарник не запускают, поэтому в отчёт они не
  попадают — но вы увидите их в терминале/редакторе при запуске тестов.
  Задание при этом просто останется «не решено».
- Названия папок — это имена Go-пакетов, поэтому используйте ASCII-slug'и
  (`peremennye`, а не «переменные»); заголовок задаётся в `task.json`/`topic.json`.
- На production раздел пуст: там нет каталога `exercises/`. Это ожидаемо —
  тесты запускаются только там, где есть исходники.
